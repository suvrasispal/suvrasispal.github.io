Running this at the bar

The inventory service ships with this application and is how the bar should run it. It owns data/inventory.xlsx and serves the app itself, so every device sees the same stock.

Start it on the bar's computer: npm install then npm start, and open localhost:4000. Tablets and phones on the same wi-fi use that computer's local address. The app finds the service on its own — the status chip in the header turns green.

How it saves. Each change is sent to POST /api/inventory, written into the workbook, and read straight back, so the screen always shows what the file holds. The app re-reads via GET /api/inventory every few seconds and on tab focus, which is how another bartender's change appears here. A save that does not reach the workbook is refused and reported, never silently kept in the browser.

The buttons above are for when the service is not running — one machine, one browser, no sharing. Replacing Excel with a database later means rewriting the service's two read/write functions; this interface is unchanged.
